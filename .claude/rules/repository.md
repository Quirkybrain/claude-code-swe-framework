# Repository Management Rules

- Follow the current user instruction first. Read `config/git-policy.json`; use its configured company policy under `input/` for applicable clauses, otherwise use `config/git-policy.default.md`. Pin the policy file and section in every handoff when configured. Follow [Git collaboration](../../docs/git-collaboration.md).
- Before mutation, inspect branch, HEAD, status, worktrees, active handoffs and remote tracking state. Preserve a committed baseline. Keep unrelated user files out of every commit and merge. Do not make an empty baseline commit when HEAD already represents a clean workspace.
- `repository-manager` prepares one typed integration branch (`feat/`/`feature/`, `fix/`/`bugfix/`, `hotfix/`, `docs/`, `refactor/`, `test/`, `chore/`, or optional `release/`) from refreshed main and one task branch/worktree per small delegated task. Fetch at integration-branch creation and merge boundaries when a remote exists; fast-forward pull only a clean tracking branch. Never pull, switch, rebase, merge, or move a branch while its specialist handoff is active.
- Each specialist stages and commits only its pinned `commit_paths` on its task branch after role-specific validation. Report-only roles may change only their declared reports. `finish` verifies scoped commit ancestry, subject policy, deliverables and clean target paths. Review corrections are new commits and require renewed checks.
- After a task Gate passes, `repository-manager` owns `repository_action: merge` from task to its integration branch. After all task integrations, integration/regression tests, independent review and Stage Gate pass, it uses a hosted PR/MR for protected main when `main_merge_mode` requires it, or a guarded local merge when that setting allows it. Declare source/target, output paths, persistent evidence report and snapshot predecessors. Verify pinned tips, merge commit and result. Failed or stale tasks cannot enter integration.
- A `repository-manager` handoff can use `status` for read-only evidence or `commit` for its own exact `commit_paths`. Status inspection itself does not require delegation. Recovery snapshots are separate from normal commits.
- Never reset, clean, force-push, silently rewrite reviewed commits, commit credentials, or merge unresolved conflicts to simulate compliance. Pushing, deployment and branch deletion are separate actions.
